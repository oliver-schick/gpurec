## Workstream 2 — Exactly replicate AleRax's presence counting  ✅ DONE + verified
**Bug:** gpurec marked a species node "present" on **visit** (`occupied`, set at the top of every
recursion) — including transfer-in→TL-lost, transfer-source, and D-only transients that carry **no
surviving copy**. AleRax (`GeneRaxCore/src/util/Scenario.cpp`, `gatherReconciliationStatistics`) sets
`eventCount[4]` (presence) `= 1` **only** at `EVENT_S / EVENT_SL / EVENT_None(leaf)` — i.e. `copies[s] ≥ 1`.
(gpurec `copies` = S+SL+leaf already matched AleRax exactly, ratio 1.000.)

**Fix (both engines):** presence incremented only at the S/SL/leaf exits, deduped one mark per
(node, sample) — `mark_present()` in `gpurec/core/cpp/recon_sampler.cpp` (the default engine) and the
event-based occupancy set in `experiments/per_node_copies.py` (main py path + cpp-vs-py validate path).
Also: the root self-check now validates the **origination** tally vs analytic origination (presence@root
is legitimately ≤ origination@root now — a family can originate at the root yet leave no surviving copy).

**Verification (job 4641254, COMPLETED):** leaf ratio 1.034→**1.000**; DPANN 1131→**914**; mean 1.078→**0.981**;
sd 0.058→0.041. The cpp `.so` was force-rebuilt (`rm -rf .torch_ext/recon_sampler`) from the new source.

**Note for future work:** *all genome numbers produced before `6b9adbf` used the inflated (visit) presence.*
Anything quoting per-node "presence/genome size" (e.g. FULLbasin DPANN ~2814, rfx-pO 1121, both-het, the
clade-vs-branchwise report Fig 2/4) should be **re-sampled** with the fixed sampler before citing — the
fix lowers presence most in deep, transfer-heavy clades.
