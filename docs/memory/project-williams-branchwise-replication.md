GOAL (started 2026-06-18): replicate AleRax's BRANCH-WISE (per-species-branch) DTL rate results with gpurec on the Williams et al. 2017 archaeal dataset, USING the fraction-missing (per-leaf p_obs) feature. "Branch-wise" == gpurec's `specieswise` mode (theta shape [S,3], cols [D,L,T], rate = 2**theta).

ALL inputs are present on Saion inside `/work/SzollosiU/gergely-szollosi/3_Reconciliation.tar.gz` (only Williams_et_al_2017/rooted_phylogeny/ is extracted; rest must be read from the tarball). See [[reference-saion-reconciliation-data]].
- Gene families: `Williams_et_al_2017/ccps/*.ale` (5,446; ALEobserve format). Leaf labels = `Species_geneNumber` (e.g. `Lokiarch_1099`); species = prefix before the last `_<digits>` (gpurec default_species_of_leaf = prefix before FIRST `_`, which also works here).
- Rooted species trees: `Williams_et_al_2017/rooted_phylogeny/{Alti,AMD,Asgard,Cluster2,DPANN,Eury,HaloThermoplas,Kor,TAC,TackA}` (Newick, short labels Tkoda/Pfuri/... matching .ale species prefixes). 10 candidate roots.
- REFERENCE to match: `Williams_et_al_2017/reconciliation models/branch wise/<clade>/model_parameters/model_parameters.txt` (per-branch rates; cols ~D,T,L + a 5th near-constant O/origination col; ~18 distinct tuples for Eury). Also `global/` (3 cols) and `family wise/<clade>/...rates.txt` (header `# D L T`).
- fraction_missing: `Williams_et_al_2017/fraction_missing` (tab-sep `taxon\tfraction`, e.g. `ThaumE09\t0.855`). fraction_missing = 1 - p_obs.

CRITICAL IMPLEMENTATION GAP: fraction-missing is NOT in gpurec's production GPU path.
- E boundary (E_l = 1-p_obs): implemented in `core/likelihood.py` `E_fixed_point(leaf_E=[S] log2(1-p_obs))` but NOT forwarded by the model.py E wrapper or the optimizer.
- Pi leaf boundary (Pi_{l,gamma}=sigma+(1-sigma)(1-p_obs)): implemented ONLY in `core/legacy.py` (test-only full-matrix CPU). NOT in the wave forward `core/forward.py` / wave backward / optimizers.
- No `GeneDataset.from_ale` / `GeneReconModel.from_ale` (only `io/ale.py:parse_ale_file` + `build_family_from_ale`); no per-species fraction_missing plumbed through dataset/optimizer; no CLI flag.
So a faithful GPU branch-wise run WITH fraction-missing needs: (1) thread leaf_E into the production E solve; (2) add the Pi leaf (1-p_obs) seed in the wave forward (backward may be ~free if it reads saved forward Pi activations -- VALIDATE with finite-diff vs legacy); (3) build dataset from .ale + species tree + fraction_missing vector; (4) validate wave+fm likelihood == legacy CPU reference; (5) optimize specieswise; (6) compare to the branch-wise model_parameters.txt.

KEY FINDING (fraction-missing, verified 2026-06-19): gpurec's fraction-missing is FAITHFUL to AleRaxSupp.tex -- NO 1-fraction_missing/sign error. leaf_E = log2(fraction_missing) = log2(1-p_obs) correctly realizes E_l=1-p_obs (supp L116, used as single-factor p^S*E_l in terminal E L111) AND the Pi leaf boundary Pi_{l,g}=sigma+(1-sigma)(1-p_obs) (supp L159). The file IS fraction_missing (=1-p_obs), confirmed by values (Kcryp 0.003 = near-complete genome; absurd as p_obs). BUT enabling fm INFLATES the inferred LOSS rate (not lowers it as intuition suggests) -- this is CORRECT per the supp, caused by the observability/ascertainment DENOMINATOR sum_e p^O_e(1-E_e): fm raises extinction E_e, shrinking (1-E_e), so the optimizer is rewarded for higher extinction = higher D/T/L rates. Decomposition: dNLL/dL flips sign with fm (numerator goes flat, denominator drives loss UP). Consequence: fm + FREE per-branch rates -> loss unidentifiable / runs to boundary -> MUST regularize (the Brownian prior) or constrain. EMPIRICALLY gpurec WITHOUT fm matches the AleRax branch-wise reference (D~0.06/L~0.39/T~0.17 vs AleRax 0.075/0.22/0.14), so the AleRax reference was evidently run with p_obs=1 (NO fraction-missing); comparing gpurec-with-fm to that reference is apples-to-oranges. WITH fm all 3 prior configs inflate loss (loose L~29, tight L~18, bounds L pegged at 10). Complete archaea60 set (incl small_fams, ~31,236 families, /work/SzollosiU/gergely-szollosi/archaea60/small_fams) maps cleanly to the Eury tree (60 species, 0 mismatches).

ROOT CAUSE (found 2026-06-19 by reading AleRax source github.com/BenoitMorel/AleRax src/ale/UndatedDTLMultiModel.hpp): the AleRax SUPPLEMENT contradicts the AleRax CODE on the Pi leaf boundary. AleRax applies fraction-missing (`_fm`) ONLY in the extinction E recursion (line 404: `_PS[ec]*_fm[e]`, the "S but not observed" term) -- it is the ONLY use of `_fm` in the whole model. The Pi (uq) reconciliation recursion does NOT use `_fm`: the leaf boundary is just `proba += _PS[ec]` at the mapped gene-leaf (sigma=1), with NO `(1-sigma)(1-p_obs)` baseline. But AleRaxSupp.tex L159 DOES include `Pi_{l,g}=sigma+(1-sigma)(1-p_obs)`, and gpurec faithfully implemented the SUPPLEMENT -> gpurec has an EXTRA Pi leaf-boundary term that AleRax lacks. FIX to match AleRax: keep leaf_E in the E solver but DROP the Pi baseline (don't pass leaf_obs_log into Pi_wave_forward) = "e-only" fraction-missing mode (driver flag `--fm-mode {off,both,e-only}`; decoupled leaf_E/leaf_obs_log in optimize_theta_wave + implicit_grad). CONFIRMED on Williams Eury (3946 fam): e-only L median 0.39 vs supplement `both` 17.8 (no-fm 0.46) -- inflation GONE; matches AleRax per-branch D Pearson 0.63, T 0.55. So the Pi double-count is the SOLE cause; the ascertainment-denominator/E-side effect is negligible at scale. Mathematically the E-only (code) form is consistent; the supplement Pi baseline double-counts the present-but-unobserved mass already in E_l (complementarity). (AleRax submodule = noahares/GeneRaxCore, Noah's fork.)
